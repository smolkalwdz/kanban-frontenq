# Видео в слайд-шоу телевизоров

## Цель

Разрешить администратору загружать MP4-видео вместе с изображениями. Обновлённое
Tizen-приложение должно показывать смешанный плейлист, когда HDMI/PS5 недоступен:

- изображение показывается 7 секунд;
- видео воспроизводится целиком до события `ended`;
- после завершения текущего элемента включается следующий;
- после последнего элемента плейлист начинается сначала.

Видео уже не содержат аудиодорожки. Приложение не должно принудительно задавать
`muted`.

## Совместимость обновления

Существующий `GET /api/tv/slides` сохраняется без изменений и продолжает отдавать
только URL изображений. Это позволяет старым версиям Tizen-приложения работать,
пока телевизоры обновляются постепенно.

Добавляется `GET /api/tv/media`, который возвращает смешанный список:

```json
[
  { "type": "image", "url": "https://.../slides/example.jpg" },
  { "type": "video", "url": "https://.../slides/example.mp4" }
]
```

Поддерживаемые форматы:

- изображения: JPG, JPEG, PNG, WEBP;
- видео: MP4.

## Backend

Файлы продолжают храниться в общей папке `slides`. Endpoint загрузки принимает
изображения и MP4, но проверяет расширение и MIME-тип. Ограничения:

- не более 20 файлов за один запрос;
- не более 100 МБ на один видеофайл;
- не более 15 МБ на одно изображение.

`GET /api/tv/slides` фильтрует только изображения. `GET /api/tv/media` возвращает
изображения и MP4 с явным типом. Endpoint удаления остаётся общим для обоих типов.

Порядок элементов соответствует времени загрузки файлов на сервер. Используется
одна общая очередь, например:
`картинка 1 → картинка 2 → видео → картинка 3 → повтор сначала`. Новые файлы
добавляются в конец очереди; ручная перестановка элементов в эту версию не входит.

## Админ-панель

Вкладка «Слайды» переименовывается визуально в «Медиа на TV».

- Поле выбора принимает изображения и MP4.
- Изображения отображаются обычным превью.
- Видео отображаются через элемент `video` с контролами только для локального
  предпросмотра в админке.
- Каждый элемент можно удалить существующей кнопкой.
- Ошибки загрузки и удаления показываются пользователю.

## Tizen-приложение

В разметку добавляется отдельный `<video>` рядом с `<img>`. Одновременно видим
только один из элементов.

Логика проигрывателя:

1. Раз в 60 секунд приложение загружает `/api/tv/media`.
2. При отсутствии HDMI запускается первый элемент плейлиста.
3. Для изображения создаётся таймер на 7 секунд.
4. Для видео вызывается `play()` без принудительного `muted`; переход выполняется
   по событию `ended`.
5. При ошибке загрузки изображения или видео элемент пропускается.
6. При появлении HDMI таймер изображения очищается, видео останавливается и
   скрывается.
7. При повторном исчезновении HDMI плейлист запускается с первого элемента.
8. Если список пуст, остаётся чёрный фон.

Уведомления и индикатор громкости продолжают отображаться поверх слайд-шоу.

## Развёртывание

Порядок безопасного обновления:

1. Обновить backend с новым совместимым endpoint.
2. Обновить frontend админ-панели.
3. Собрать новый WGT.
4. Устанавливать новую версию Tizen-приложения на телевизоры.

До шага 4 старые телевизоры продолжают получать только изображения через старый
endpoint.

## Проверка

- Unit-тест классификации файлов и формирования медиаплейлиста.
- Unit-тест переходов плеера: изображение по таймеру, видео по `ended`, ошибка
  пропускает элемент.
- Проверка production-сборки frontend.
- Проверка синтаксиса backend и Tizen JavaScript.
- Ручная проверка WGT сначала на одном телевизоре: картинка → MP4 полной
  длительности → картинка → появление HDMI → возврат к плейлисту.
